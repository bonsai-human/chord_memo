# Chord Memo

作曲や練習のための、グリッドベースのコード進行メモツール。ブラウザだけで動きます。

拍のグリッドにコードを置いて、そのまま鳴らして確かめられます。YouTube や手持ちの音源と同期させて、曲を聴きながらコードを拾うこともできます。

## 主な機能

- **グリッド入力** — 1マス＝1拍。クリックして下部のキーボードでコードを置く
- **コードキーボード** — ダイアトニック / クオリティ / テンションの3タブ。ルートとオンコードのベースを個別に指定できる
- **リズム分割** — 4分・8分・16分・4分3連・8分3連
- **小節ごとの設定** — キー・テンポ・拍子・スウィング。キーを変えるとそこから先のコードが自動で移調される
- **セクションラベルと参照再生** — 「Aメロ」などのラベルを付け、別の場所からループ回数つきで参照できる
- **再生** — 音域を指定したボイシング最適化、メトロノーム、スウィング、ループ
- **同期再生** — オーディオファイル（開始位置の自動検出つき）と YouTube。動画に追従してコード進行が進む
- **コピー & ペースト** — そのまま貼り付けと、貼り付け先のキーに合わせた移調貼り付け
- **操作履歴** — 50件まで遡れ、任意の時点へ飛べる
- **度数表記** — コード名を I, IV, V… に切り替え
- **書き出し** — JSON（バックアップ用）/ rechord.cc 形式 / ChordPro 形式
- **操作マニュアル** — ヘッダの ? から。基本操作・コードキーボード・小節設定・その他の4タブ
- すべてブラウザのローカルストレージに自動保存されます（サーバーへは何も送りません）

## 使い方

グリッドをクリックして拍を選び、下部のコードキーボードでコードを入力します。

| キー | 動作 |
|---|---|
| `Space` | 再生 / 停止 |
| `Ctrl` + `C` | コピー |
| `Ctrl` + `V` | 貼り付け |
| `Delete` / `Backspace` | コード削除 |
| `Shift` + クリック | 範囲選択（範囲選択モード時） |

アクションバーの一部のボタンは**長押し（右クリック）でメニュー**が開きます。貼り付けなら「キーに合わせて貼り付け」、削除なら「小節ごと削除」、元に戻す・やり直しなら操作履歴の一覧です。

## 開発

```bash
npm install
npm run dev
```

```bash
npm run build
```

`vite.config.ts` の `base` はサブディレクトリ配信を前提に `/chord_memo/` にしてあります。ルート直下で配信する場合は `/` に変えてください。

## 技術構成

Vite + React + TypeScript。音は [Tone.js](https://tonejs.github.io/)、アイコンは [lucide](https://lucide.dev/)、動画同期は YouTube IFrame Player API を使っています。外部フレームワークに寄せず、状態はすべて React のローカルステートで持っています。

データはブラウザに保存されます。プロジェクトは localStorage、同期用のオーディオファイルは IndexedDB です。

## 音源について

演奏に使うサンプル音源は [tonejs-instruments](https://github.com/nbrosowsky/tonejs-instruments) から読み込んでいます（CC-BY 3.0）。リポジトリには含まれません。

## このリポジトリについて

このアプリは以前レンタルサーバーで公開していたものですが、AI エージェントの誤操作でソースコードを失いました。手元に残っていたのはビルド済みの JavaScript だけです。

そこで、公開されていたビルド成果物を解析して仕様を復元し、そこから作り直したのがこのリポジトリです。元のソースコードそのものではなく、挙動を揃えて新しく書き直したものです。復元した仕様は [SPEC.md](SPEC.md) にまとめてあります。

なお参照元にしたビルド成果物は、第三者ライブラリのコードを含む配布物のため、このリポジトリには含めていません。

## 配信

GitHub Actions で GitHub Pages へ配信しています（`.github/workflows/deploy-pages.yml`）。main に push すると自動でビルドされます。

## PWA には対応しません

元アプリのヘルプには「PWA 対応」と書かれていましたが、実際には Service Worker の登録と解除が競合して機能していませんでした（[SPEC.md](SPEC.md) 12章）。作り直すにあたって、以下の理由で対応しないことにしました。

- プロジェクトは localStorage、同期音源は IndexedDB と、データはもともと端末内にある
- 演奏サンプルを外部（tonejs-instruments）から取得しているため、オフラインにしても音が鳴らない。全音色をキャッシュするか同梱しない限り解決せず、容量に見合わない

なお `apple-mobile-web-app-capable` は残してあるので、iOS では「ホーム画面に追加」から全画面で起動できます（起動のみ。通信は必要です）。

## 未実装・既知の制限

- 読み込みは JSON のみ。rechord.cc / ChordPro の取り込みには対応していません
- 再生位置に合わせたグリッドの追従スクロールはありません
- 16分などでマスが極端に細かく、かつ隣のマスも埋まっている場合、長いコード名は最小サイズまで縮んだあと折り返します
- ボイシングは指定音域へ引き寄せるだけで、前後のコードとのボイスリーディングは行いません（元アプリと同じ挙動。ヘルプの記述はこの実装に合わせてあります）
